Cloud cost and security posture for the cloud connections Obzly already scans, with
recommendations for both, in one release. Obzly only reads: it never buys, changes or deletes
anything in your clouds. The design is in [CLOUD_COST_POSTURE.md](../CLOUD_COST_POSTURE.md).

## Cost

Turn on **Cost** for an AWS account or Organization, or an Azure subscription or management group,
in the cloud connection wizard.

- **Where the numbers come from**, chosen per connection, with what each costs:
  - **Automatic** (default): a FOCUS 1.2 export (AWS Data Exports to S3, Azure Cost Management to a
    storage account) for resource-level and amortized cost, with the billing API filling in until
    the first export lands. A day comes from one source, never both.
  - **Export only**, or **API only** (Cost Explorer at $0.01 per request; Azure's query API is free
    but throttled).
- **Billing scope:** a management account or billing scope reads cost for its members once; a
  member connection shows "Cost via ..." and never counts it again.
- **Cost tab** (control plane, every Site you can reach):
  - **Overview:** month to date, forecast and last month per currency, the daily trend with
    estimated days and anomalies marked, top services and accounts, and what each connection last
    delivered.
  - **Explorer:** preset or custom ranges, daily to yearly, grouped by provider, account, region,
    service, resource, charge or a tracked tag, with filters that follow each other. Drill down,
    copy as CSV, and save views (shared or private, with a default). Amounts are never added across
    currencies, and a period without data shows n/a, not 0.
  - **Budgets and anomalies:** monthly budgets per scope that alert on the forecast, and anomalies
    against the same weekday, sent to the shared notification channels.
- **Infrastructure:** the asset drawer shows a resource's cost over 30 days.

## Posture

Turn on **Security posture** for a connection.

- **Sources**, chosen per connection: **Automatic** (Security Hub or Defender for Cloud where
  they're on and readable, Obzly's own baseline checks elsewhere), **Native only** or **Baseline
  only**. Each region (AWS) or subscription (Azure) reads from one source, so a finding is never
  counted twice.
- **Obzly baseline:** 19 checks to start (12 AWS, 7 Azure) written in CEL, each mapped to AWS FSBP,
  CIS or MCSB controls, with fix steps for the CLI, IaC and console. They run in the probe; only
  findings and minimal evidence leave it.
- **Findings** open, resolve and reopen with their history. A finding resolves only when its scope
  was read again successfully. Suppressing one needs a reason, can have an end date and is audited.
- **Posture tab:** a score per standard, findings with their fix steps, trends with saved views,
  and coverage per region or subscription with the reason it falls back. New critical and high
  findings can alert on the project's channels.
- **Infrastructure:** the asset drawer shows a resource's open findings.

## Recommendations

- **Cost → Recommendations**, read weekly:
  - rightsizing, idle and modernization from Compute Optimizer and Azure Advisor, plus Obzly's own
    checks (unattached volumes and disks, gp2 volumes, unused IP addresses);
  - on EC2, the Obzly agent's CPU and memory p95, since CloudWatch has no memory figure; a busy
    memory marks the recommendation high risk;
  - plan, finish or dismiss each one; done is also detected when the provider stops recommending
    it, and realized savings are measured from cost data 14 days before and after;
  - existing Savings Plans and reservations, flagged when unused or ending within 60 days (which
    also alerts);
  - a commitment planner comparing 1 and 3 years by payment option for a 7, 30 or 60-day look-back,
    from the providers' own purchase recommendations, with **Rightsize first** so the plan and the
    rightsizing list never count the same saving twice, and the console steps to buy.
- **Posture → Recommendations:** actions ranked with coverage gaps first, then by severity closed
  per unit of effort; guardrails that stop findings coming back (S3 Block Public Access, IMDSv2 and
  EBS encryption by default, Azure Policy denies); a plan, with each standard's score shown as it
  would be with the plan done. An action whose findings were suppressed instead of fixed shows as
  an accepted risk, not done.

- **MCP:** read-only tools `cost_summary`, `cost_explore`, `cost_anomalies`, `cost_budgets`,
  `cost_recommendations`, `posture_scores`, `posture_findings` and `posture_coverage`, scoped to
  the caller's projects.
- **Fixes:**
  - `./main --email ...` (password reset), `--reset-mfa` and `--reset-bootstrap-token` now work
    inside a running container: they run before the server starts anything, where they used to
    fail because the running server already held the metrics port.
  - SSO connectors that share an identity provider discover it once, instead of once per connector
    at the same moment.
  - Service names on Incidents are readable in both themes.

## Upgrading

Three new migrations, all additive; rolling back to v1.0.0 is supported. Upgrade the Sites, then
the control plane, then the probes: probes older than v1.1.0 don't read cost or posture. If a
Site's ingress only admits the control plane apart from ingest paths, also let the probes reach
`/v1/cloud/cost`, `/v1/cloud/posture` and `/v1/cloud/advice`. Connections that add Cost or Posture
need their CloudFormation stack, Bicep deployment or CLI script updated from the wizard; inventory
alone needs nothing. Details: [the upgrade runbook](../runbooks/upgrade.md#releases-that-need-action).
