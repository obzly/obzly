Fixes for issues found running v1.2.0 in production, plus dashboards and alerts from SQL results and
a more compact ingestion status.

## Highlights

- **SQL results to dashboards and alerts:** a Logs SQL chart now has **Save to dashboard** and
  **Create alert**. Dashboards gain SQL panels (line, ranked list, donut, table, stat) that run over
  the dashboard's time range, and alert rules gain a **Logs SQL** source: each result row is one
  series, its `value` column (or last number) the value and the other columns its labels.
- **Ingestion status:** one tile of four counts (sources, sending, quiet, stopped) on the project
  Overview and on Data sources; click any of them for the full list, sortable and filterable by
  health, signal and name.
- **Synthetics:** active outages and certificates expiring soon now sit at the top of the overview.

## Fixes

- **Logs:** Volume & noise, Health map, Web analytics and the Chart view no longer show "Running
  query" forever: the hidden Search results kept loading page after page behind them.
- **Web analytics:** reports and hourly rollups no longer fail with "Malformed JSON" on projects
  with non-JSON log lines.
- **Worker memory:** the infrastructure inventory build and the Web analytics rollups ran out of
  memory under v1.2.0's worker caps on every run, so the inventory stopped updating. Both now fit
  the caps.
- **Synthetics** sent every monitor query twice when the page opened; once now.
- **Alerts:** rules kept by Cost and Posture are tagged as such instead of "Synthetics".
- **Docker:** `deploy/docker/.env.example` pins the release image instead of `latest`, which
  pointed at an old release.

## Upgrading

One new migration (alert rules accept the Logs SQL source). Upgrade the Sites, then the control
plane, then the probes. Before rolling back to v1.2.0, delete any Logs SQL alert rules and SQL
dashboard panels. Details: [the upgrade runbook](https://github.com/obzly/obzly/blob/main/docs/runbooks/upgrade.md#releases-that-need-action).
