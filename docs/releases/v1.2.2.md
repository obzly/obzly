Fixes for issues found running v1.2.1 on a large production project (about 150 million log lines
a day), a compact Synthetics overview, and a choice of how far to trust an SSO provider's MFA.

## Highlights

- **Synthetics overview:** Availability can show every monitor as a **honeycomb**, one cell per
  monitor with failing ones first, coloured by status or by p95 response time and grouped by
  folder. It is the default above 50 monitors, and each person's choice is remembered. Location
  health shows one small honeycomb per location, each monitor in the same place in all of them,
  then only the monitors failing somewhere. Slowest monitors keeps its own height, and any "Show
  all" list scrolls inside its panel.
- **SSO MFA trust:** each SSO connector now trusts the provider's MFA **off**, **when the ID token
  shows MFA** (`amr`), or **always** (the provider enforces MFA for everyone who can sign in
  through it). Choosing *always* shows a warning. After an SSO sign-in that didn't report a second
  factor, the MFA screen says why Obzly asks for its own. Amazon Cognito reports MFA in `amr` only
  with managed login and MFA configured; users federated through it show `fed`.
- **Infrastructure** no longer loads every asset from every Site when it opens. Assets are paged,
  sorted and filtered on the Site ("Showing a–b of M"), the tree loads children when a branch
  opens, and nothing is cut off silently at 5,000 assets any more.

## Fixes

- **Logs › Patterns, Volume & noise, Health map and the Anomalies badge** ran out of memory on
  projects with many patterns or pods: each counted every group in every hour before picking the
  top ones, which crashed the Site API (4 GiB) and returned 502 after about a minute. The top
  groups and the comparisons with earlier periods are now picked in the merge query, so only the
  rows shown reach the API: in tests with 30,000 patterns a top 10 over 48 hours went from 394,341
  rows and 679 ms to 12 rows and 22 ms. Patterns counts its 7-day baseline only for the patterns it
  shows, and Volume's "other" is the day's total minus the top services. Explain this spike, the
  pattern changes and dashboard top-N panels use the same path.
- **Web analytics** hourly rollups failed on every run on projects with many non-access log lines
  (temporary disk full or the deadline passed), so no hour ever closed and every report fell back to
  a slow live scan. The scan now reads only the timestamp, message and fields, skips lines that
  can't be access logs while it reads them, and builds the table in one pass instead of copying the
  whole hour first. A busy hour is read in slices, halved again if one still runs out of memory, and
  hours with no access logs close. If the live part of a report can't finish in 20 seconds, the
  report still shows the closed hours and marks the live part as partial.
- **Worker logs:** routine compaction, retention, correlation and quota passes log at debug; a
  retention pass that deleted data, and every failure, still log.
- **Sidebar:** each item is a button with its name, reachable with Tab and announced by screen
  readers.

## Upgrading

One new migration (SSO connectors gain `mfa_trust`; connectors that trusted the provider's MFA
become `amr`, so sign-ins behave as before). Upgrade the Sites, then the control plane, then the
probes. A rollback to v1.2.1 is safe: it treats an `always` connector as `amr`. Details:
[the upgrade runbook](https://github.com/obzly/obzly/blob/main/docs/runbooks/upgrade.md#releases-that-need-action).
