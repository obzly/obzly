A new look for the whole app, a project Overview, Web analytics from your access logs and new ways
to explore logs, plus fixes for worker memory and slow long-range queries.

## Highlights

- **UI v2:** every page restyled into cards, KPI tiles and charts, with all existing features kept.
  Project settings, members, API keys and data sources are grouped under one **Settings** item.
- **Themes:** the theme button in the top bar now opens a menu with six themes (Emerald light/dark,
  Soft light, Semi-dark, Midnight, Black), a System mode and colour-blind safe chart colours. The
  choice is saved to your profile; admins set defaults in Obzly settings › General › Appearance,
  and `?theme=black` forces a theme on a wall screen.
- **Overview:** a new landing page per project: log volume, error rate, p95, incidents, services
  with the most errors, budgets and quotas, synthetics and infrastructure, each linking to its page.
- **Web analytics** (Logs): a GoAccess-style report built from the access logs you already send
  (nginx, Apache, Envoy, Traefik, IIS): visitors, URLs, 404s, referrers, browsers, countries and
  more, per source. Hourly rollups plus the live hour; client IPs are truncated by default.
  Countries use the bundled DB-IP Lite database (CC BY 4.0).
- **More ways to explore logs:** Chart view for any search or SQL result (save to a dashboard or
  create an alert from it), time heatmaps, compare two ranges, Explain this spike, Pattern trends,
  Volume & noise with pattern sampling rules, and a Health map.
- **Notifications:** alert rules get a severity (Critical, High, Medium, Low) and a runbook
  description; messages start with a severity emoji, Slack messages get a coloured side bar and
  PagerDuty the matching severity. **Message templates** (Obzly settings › Notifications &
  alerting) edit what email, Slack, PagerDuty and webhooks send, organisation-wide or per channel,
  with a live preview, Send test and Reset to default; on a control plane they reach the Sites with
  the channels. **Incident notifications** (Incidents › gear icon) notify a project's channels when
  an incident opens and ends. See
  [configuration](https://github.com/obzly/obzly/blob/main/docs/configuration.md#email-and-notification-channels).
- **MCP server:** 23 new read-only tools (alerts, trace summary, incident impact, log insights,
  dashboard panel data, ingestion status, inventory, AI usage, synthetics, web analytics), output
  schemas and structured results, cursor paging, resources and prompts. Optional **write tools**
  (create or expire a silence, create a dashboard, add a panel) need the new `mcp:write` scope, are
  off by default, need MFA, ask for confirmation, are rate-limited and audit-logged; silences made
  this way are limited to 4 hours and show who created them.
- **Everywhere else:**
  - Dashboards: stat with trend, ranked list, donut, gauge, stacked bars and status strips.
  - Alerts: activity per rule.
  - Service map: health, rate and p95 per service.
  - Traces: summary tiles and a total match count.
  - Incidents: impact by service.
  - Data sources: ingestion status.
  - Users: summary and filters.
  - Previous-period changes on KPI tiles.
  - Settings › Updates: an upgrade order card.
  - Cost: a Summary view with posture.

## Fixes

- **Worker memory:** every DuckDB handle is capped, workers' search handles are smaller and
  share capped compactor and writer databases, and each worker logs its memory budget at startup.
  Interval tasks (inventory, retention, compaction, correlation, ...) run once per interval across
  workers instead of on every worker.
- **MCP:** searches report when they were partial, large results are trimmed to whole items,
  cancelling a call stops its query, windows are capped (31 days logs/traces, 92 days metrics), and
  tools can only call the read endpoints they need.
- **SQL mode** (Logs and MCP) refuses DuckDB's introspection and file functions (`duckdb_*`,
  `current_setting`, `read_*`, `query()`, ...), which could reveal server settings.
- **Long-range queries:** instant PromQL over days (e.g. Synthetics' 7-day uptime) is split across
  the queriers instead of read cold on an API pod; service map and trace summary queries run on a
  warm querier; segment downloads finish into the cache even when the query that started them
  times out.

## Upgrading

Eight new migrations, all additive; rolling back to v1.1.0 is supported. Existing alert rules take
their severity from their `severity` label (Medium when there is none). Upgrade the Sites, then the
control plane, then the probes. Settings › Updates now asks GitHub for the latest release every 6
hours; set `UPDATE_CHECK=false` to turn that off. Details: [the upgrade runbook](https://github.com/obzly/obzly/blob/main/docs/runbooks/upgrade.md#releases-that-need-action).
